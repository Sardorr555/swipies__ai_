# Quickstart
import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';
import APITable from '@site/src/components/APITable';

Swipies is an AI-powered RAG (Retrieval-Augmented Generation) engine based on deep document understanding. When integrated with LLMs, it is capable of providing truthful question-answering capabilities, backed by well-founded citations from various complex formatted data.

This quick start guide describes a general process from:

- Understanding Swipies editions and license versions,
- Starting up a local or server Swipies instance, 
- Activating your license key,
- Creating a dataset, 
- Intervening with file parsing, to 
- Establishing an AI chat based on your datasets.

:::danger IMPORTANT
We officially support x86 CPU and Nvidia GPU, and this document offers instructions on deploying Swipies using Docker on x86 platforms. While we also test Swipies on ARM64 platforms, we do not maintain Swipies Docker images for ARM.

If you are on an ARM platform, follow [this guide](./develop/build_docker_image.mdx) to build a Swipies Docker image.
:::

### How to Acquire a Swipies License

1. Visit the official portal: [https://swipies.app](https://swipies.app).
2. Sign in to your account and navigate to **User Settings > License** (or contact [support@swipies.app](mailto:support@swipies.app)).
3. Generate or copy your cryptographic license key (e.g. `SWPIES-ENT-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`).

### How to Activate Your License

You can activate your Swipies license through any of the three methods below:

#### Method 1: Environment Variable (Recommended for Docker / CI/CD)
Set the license key directly in your `docker/.env` file before starting the stack:

```bash
SWPIES_LICENSE_KEY="SWPIES-ENT-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```
On boot, Swipies validates the cryptographic signature offline and unlocks all Enterprise capabilities automatically.

#### Method 2: Web Interface (GUI)
1. Open your browser and navigate to your Swipies installation: `http://<YOUR_SERVER_IP>`.
2. Log in with your administrator account.
3. Click your profile avatar in the top-right corner **>** **System Settings** **>** **License**.
4. Paste your key and click **Activate License**.

#### Method 3: REST API (Automated Provisioning)
```bash
curl -X POST http://<YOUR_SERVER_IP>:9380/v1/system/license \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <ADMIN_ACCESS_TOKEN>" \
  -d '{"license_key": "SWPIES-ENT-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"}'
```

:::tip Detailed Guide
For complete instructions on air-gapped deployments, hardware requirements, key renewal, and offline validation, see the [License Activation & Self-Hosted Guide](./guides/license_activation.md).
:::

## Prerequisites

- CPU &ge; 4 cores (x86);
- RAM &ge; 16 GB;
- Disk &ge; 50 GB;
- Docker &ge; 24.0.0 & Docker Compose &ge; v2.26.1;
- Python &ge; 3.13;
- [gVisor](https://gvisor.dev/docs/user_guide/install/): Required only if you intend to use the code executor ([sandbox](https://github.com/Sardorr555/swipies__ai_/tree/main/sandbox)) feature of Swipies.

:::tip NOTE
If you have not installed Docker on your local machine (Windows, Mac, or Linux), see [Install Docker Engine](https://docs.docker.com/engine/install/).
:::

## Start up the server

This section provides instructions on setting up the Swipies server on Linux. If you are on a different operating system, no worries. Most steps are alike.

1. Ensure `vm.max_map_count` &ge; 262144.

<details>
  <summary>Expand to show details:</summary>

   `vm.max_map_count`. This value sets the maximum number of memory map areas a process may have. Its default value is 65530. While most applications require fewer than a thousand maps, reducing this value can result in abnormal behaviors, and the system will throw out-of-memory errors when a process reaches the limitation.

   Swipies uses Elasticsearch or [Infinity](https://github.com/swipies/infinity) for multiple recall. Setting the value of `vm.max_map_count` correctly is crucial to the proper functioning of the search components.

<Tabs
  defaultValue="linux"
  values={[
    {label: 'Linux', value: 'linux'},
    {label: 'macOS', value: 'macos'},
    {label: 'Windows', value: 'windows'},
  ]}>
  <TabItem value="linux">
   1.1. Check the value of `vm.max_map_count`:

   ```bash
   $ sysctl vm.max_map_count
   ```

   1.2. Reset `vm.max_map_count` to a value at least 262144 if it is not.

   ```bash
   $ sudo sysctl -w vm.max_map_count=262144
   ```

   :::caution WARNING
   This change will be reset after a system reboot. If you forget to update the value the next time you start up the server, you may get a `Can't connect to ES cluster` exception.
   :::
   
   1.3. To ensure your change remains permanent, add or update the `vm.max_map_count` value in **/etc/sysctl.conf** accordingly:

   ```bash
   vm.max_map_count=262144
   ```
  </TabItem>
  <TabItem value="macos">
   If you are on macOS with Docker Desktop, run the following command to update `vm.max_map_count`:

   ```bash
   docker run --rm --privileged --pid=host alpine sysctl -w vm.max_map_count=262144
   ```

   :::caution WARNING
   This change will be reset after a system reboot. If you forget to update the value the next time you start up the server, you may get a `Can't connect to ES cluster` exception.
   :::

   To make your change persistent, create a file with proper settings:

   1.1. Create a file:

   ```shell
   sudo nano /Library/LaunchDaemons/com.user.vmmaxmap.plist
   ```

   1.2. Paste the following configuration:

   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
   <plist version="1.0">
   <dict>
       <key>Label</key>
       <string>com.user.vmmaxmap</string>
       <key>ProgramArguments</key>
       <array>
           <string>/usr/local/bin/docker</string>
           <string>run</string>
           <string>--rm</string>
           <string>--privileged</string>
           <string>--pid=host</string>
           <string>alpine</string>
           <string>sysctl</string>
           <string>-w</string>
           <string>vm.max_map_count=262144</string>
       </array>
       <key>RunAtLoad</key>
       <true/>
   </dict>
   </plist>
   ```

   1.3. Set appropriate permissions:

   ```shell
   sudo chown root:wheel /Library/LaunchDaemons/com.user.vmmaxmap.plist
   sudo chmod 644 /Library/LaunchDaemons/com.user.vmmaxmap.plist
   ```

   1.4. After saving the file, load the new daemon:

   ```shell
   sudo launchctl load /Library/LaunchDaemons/com.user.vmmaxmap.plist
   ```

   :::note
   If the above steps do not work, consider using [this workaround](https://github.com/docker/for-mac/issues/7047#issuecomment-1791912053), which employs a container and does not require manual editing of the macOS settings.
   :::

  </TabItem>
  <TabItem value="windows">

   #### If you are on Windows with Docker Desktop, then you *must* use docker-machine to set `vm.max_map_count`:

   ```bash
   $ docker-machine ssh
   $ sudo sysctl -w vm.max_map_count=262144
   ```

   1.1. Run the following in WSL: 

   :::

   1.2. If you prefer not to run those commands every time you restart Docker, you can update your `%USERPROFILE%.wslconfig` as follows to keep your change permanent and global for all WSL distributions:


   *This causes all WSL2 virtual machines to have that setting assigned when they start.*

   :::note
   If you are on Windows 11 or Windows 10 version 22H2, and have installed the Microsoft Store version of WSL, you can also update the **/etc/sysctl.conf** within the docker-desktop WSL distribution to keep your change permanent:

   ```bash
   $ vi /etc/sysctl.conf
   ```

## Configure LLMs

Swipies is a RAG engine and works seamlessly with LLMs to offer grounded, hallucination-free question-answering capabilities. Swipies supports most mainstream LLMs including OpenAI, Anthropic, Azure OpenAI, DeepSeek, Google Gemini, Ollama, and local models. For a complete list of supported models, please refer to [Supported Models](./guides/models/supported_models.mdx).

:::note 
Swipies also supports deploying LLMs locally using Ollama, Xinference, or LocalAI for fully offline, air-gapped environments. 
:::

To add and configure an LLM: 

1. Click on your profile logo on the top right of the page **>** **Model providers**.

2. Click on the desired LLM and update your API key accordingly.

3. Click **System Model Settings** to select the default models: 

   - Chat model, 
   - Embedding model, 
   - Image-to-text model,
   - and reranking model.

## Create your first dataset

You are allowed to upload files to a dataset in Swipies and parse them into knowledge chunks. A dataset is a collection of documents and chunks. Question answering in Swipies can be based on a particular dataset or multiple datasets. File formats that Swipies supports include documents (PDF, DOC, DOCX, TXT, MD, MDX), tables (CSV, XLSX, XLS), pictures (JPEG, JPG, PNG, TIF, GIF), and slides (PPT, PPTX).

To create your first dataset:

1. Click the **Dataset** tab in the top middle of the page **>** **Create dataset**.

2. Input the name of your dataset and click **OK** to confirm your changes.

3. Swipies offers multiple chunk templates that cater to different document layouts and file formats. Select the embedding model and chunking method (template) for your dataset. 

   :::danger IMPORTANT 
   Once you have selected an embedding model and used it to parse a file, you cannot change it for that dataset. All files in a specific dataset must be parsed using the *same* embedding model to ensure they reside in the same embedding vector space. 
   :::

4. Click **+ Add file** **>** **Local files** to upload your files to the dataset. 

5. In the uploaded file entry, click the parse button to begin document processing.

## Intervene with file parsing

Swipies features visibility and explainability, allowing you to view the chunking results and intervene where necessary. To do so:

1. Click on the file that completes parsing to view the chunking results.

2. Hover over each snapshot for a quick view of each chunk.

3. Double-click the chunked texts to add keywords or make manual edits where necessary.

   :::caution NOTE
   You can add keywords or questions to a file chunk to improve its ranking for queries containing those keywords. This action increases its keyword weight and improves its retrieval accuracy.
   :::

4. In Retrieval testing, ask a quick question in **Test text** to verify that your retrieval pipeline returns truthful citations.

## Set up an AI chat

Conversations in Swipies are based on your configured datasets. Once you have created your dataset and finished file parsing, you can create an AI chat assistant:

1. Click the **Chat** tab in the top navigation **>** **Create chat** to create an assistant.
2. Click the created chat assistant to enter its configuration page.

3. Update **Chat settings**:
   - Name your assistant and select the datasets it should reference.
   - **Empty response**: Specify an exact response when no answer is found in your datasets, or leave it blank to allow the LLM to synthesize general answers.

4. Update the **System prompt** to tailor the assistant's personality and rules.

5. Select a chat model in the **Model** dropdown list.

6. Start chatting with your assistant!
