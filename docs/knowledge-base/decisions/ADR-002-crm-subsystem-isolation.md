# ADR-002: Изоляция подсистемы CRM и двухстадийная доставка через Outbox

## 1. Контекст и проблематика

Бизнес-требование: расширить платформу Swipies RAGFlow модулем интеграции с корпоративными CRM/ERP (amoCRM, Bitrix24, 1С:Предприятие).  
Сценарий использования: в ходе диалога AI-ассистент собирает контакты клиента (имя, телефон, суть запроса) и создает карточку сделки в CRM, а также в реальном времени проверяет складские остатки в 1С.

Технические вызовы:
1. **Ненадежность внешних CRM API:** Внешние сервисы (особенно облачные Bitrix24 или корпоративные серверы 1С) подвержены таймаутам, сетевым лагам, ошибкам 5xx и жестким лимитам запросов (Bitrix24: 2 req/s).
2. **Блокировка LLM-диалога:** Прямой синхронный сетевой вызов в CRM во время формирования ответа пользователю приводит к задержкам ответа до 5-10 секунд либо к потере лида при сетевом сбое.
3. **Безопасность учетных данных:** В существующем движке Agent Canvas и MCP Server параметры авторизации хранились в открытом виде внутри JSON DSL.

## 2. Рассмотренные альтернативы

1. **Альтернатива 1: Синхронный прямой вызов CRM из функции Tool**
   - *Плюсы:* Мгновенное получение ID сделки в диалог.
   - *Минусы:* Любое падение CRM приведет к падению ответа бота; задержки ответа бота для пользователя; нарушение лимитов rate limit.
2. **Альтернатива 2: Хранение настроек CRM в открытом DSL графа холста**
   - *Плюсы:* Использование существующего механизма Canvas.
   - *Минусы:* Грубое нарушение безопасности; компрометация токенов при экспорте холста или просмотре конфигурации в браузере.
3. **Альтернатива 3: Двухстадийная архитектура (Live Read + Transactional Outbox) с изолированным хранилищем секретов (Выбрано)**
   - *Плюсы:* Гарантия сохранности лидов (At-least-once delivery), быстрый отклик бота (<100ms), надежное шифрование кредов на уровне тенанта.

## 3. Принятое решение

1. **Разделение сценариев на Live и Outbox:**
   - **Складские остатки 1С (Live Read):** Выполняются синхронно в реальном времени, так как ответ критичен для контекста бота. Внедрен строгий таймаут 3.0 секунды, Circuit Breaker (3 ошибки / 30 сек паузы) и Graceful Fallback (вежливый ответ без поломки диалога).
   - **Создание сделок / лидов (Transactional Outbox):** Агентский инструмент `crm_lead_create` **не делает внешний HTTP-запрос напрямую**. Он валидирует телефон/данные и атомарно записывает задачу в таблицу `CRMOutboxTask` со статусом `pending`. Время отклика агента — 5-15 мс.
2. **Асинхронный воркер доставки (CRM Outbox Worker):**
   - Фоновый воркер `api/crm/tasks/outbox_worker.py` опрашивает очередь, производит дедупликацию по `idempotency_key`, применяет Rate Limiter (Leaky Bucket для Bitrix24) и доставляет сделку в CRM.
   - При сбое включается экспоненциальный backoff с сохранением полного трейса ошибки.
3. **Изолированное защищенное хранилище настроек (`TenantCRMConfig`):**
   - Учетные данные amoCRM, Bitrix24 и 1С вынесены из Canvas DSL в отдельную модель БД.
   - Все поля токенов шифруются алгоритмом AES-256-GCM + HKDF с привязкой к `tenant_id`.

## 4. Последствия и верификация

- **Положительные последствия:**
  - 100% гарантия сохранения контакта клиента даже при полном отключении серверов CRM.
  - Мгновенная отзывчивость AI-бота в интерфейсе пользователя.
  - Полная изоляция чувствительных корпоративных ключей.
- **Отрицательные последствия:**
  - Необходимость запуска фонового Outbox-воркера как постоянного сервиса.
  - Статус сделки в CRM присваивается с небольшой задержкой (eventual consistency, 1-3 секунды).
- **Верификация:**
  - 23 модульных теста в `test/test_crm_system.py` подтверждают работу всех компонентов (Rate Limiting, Circuit Breaker, Outbox Worker, Encryption, Redaction).
