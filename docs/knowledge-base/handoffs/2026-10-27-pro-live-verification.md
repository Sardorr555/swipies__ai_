# Проверка Pro-аккаунта Swipies

Дата отчёта: 2026-10-27, Asia/Tashkent. Сервер: https://api.swipies.app. Ветка исправления: `swipies_26`.

Основные сценарии внешнего агента работают на действующем сервере. Найден один воспроизведённый баг OpenAI-совместимого API; он исправлен локально и требует нового деплоя для подтверждения на сервере. Полностью исправной всю платформу по этой проверке назвать нельзя.

## Найденный баг и исправление

`POST /api/v1/openai/<chat_id>/chat/completions` на сервере возвращает HTTP 200 с бизнес-кодом 100 и сообщением `NameError("name 'LLMType' is not defined")`. Это ошибка обработчика, а не успешный ответ.

В `api/apps/restful_apis/openai_api.py` добавлен отсутствующий импорт `LLMType`. Новые четыре регрессионных случая выполняют весь обработчик: потоковый/обычный ответ × модель разрешена/запрещена. Проверка охватывает и запрет генерации при отказе политики доступа.

До исправления: **4 failed, 5 passed**, все четыре новых случая падали с тем же NameError. После: **9 passed**. Совместно с тестами API, MCP, типов моделей, каналов и прав: **95 passed**, код завершения 0.

Исправление не применялось напрямую к серверу. Обычный API чатботов и SSE проверены на сервере; OpenAI-совместимый API после исправления пока проверен локально. После деплоя требуется повторить его обычный и потоковый запросы.

## Ограничения проверки

- Ads пока не включён в MCP-каталог: фасад выбирает определённые семейства `/api/v1/*`, а рекламный кабинет зарегистрирован под `/v1/ads/*`. Чтение Ads с API-ключом работает; управление рекламой через текущие три MCP-инструмента не реализовано.
- Показы реальных кампаний, клики, платежи, модерация и списания не запускались. Нулевой рекламный кабинет не доказывает полный цикл монетизации. Ранее отдельно прошли 31 локальный Ads-тест и 2 теста Ads/billing с изолированными зависимостями.
- CRM пользователь подключит позже. Живые запросы во внешнюю CRM, доставка лидов и синхронизация внешней базы здесь не проверялись.
- Pro — тариф аккаунта, а не гарантия качества выбранной модели. На формулировку «Ответь одним словом: нефрит» модель однажды ответила «Минерал». Явное указание повторить слово выполнено; вопросы по документу отвечены правильно.
- Первые пять Ads-запросов использовали ошибочный тестовый адрес `/v1/ad/*` и вернули 404. После проверки переопределения `page_name` в коде все пять правильных `/v1/ads/*` прошли. Это ошибка проверочного скрипта. Ожидание кодового слова от стандартного RAG-чатбота до подключения документов также было некорректным; прямой чат и RAG проверены отдельно.
- Проверка не охватывает все модели, каналы, браузерный интерфейс, нагрузку и каждый из 272 маршрутов. Точный SHA работающего серверного контейнера не подтверждался по SSH.

## Состояние после проверки

Удалены созданные для аудита датасет с двумя документами, чатбот с тремя историями, агент Pro и контрольный агент Free с их сессиями. Повторное чтение удалённых ресурсов отклоняется. В аккаунте A список датасетов пуст.

Тариф остался `pro`, срок не ограничен, кредитов **512**. Рекламный баланс **0 USD**, расходов, показов, кликов, кампаний и транзакций **0**; финальные проверки не изменили эти показатели. Чтение рекламного кабинета могло создать пустой стандартный профиль рекламодателя через предусмотренный сервером `get_or_create`; профиль не удалялся.

Ключи в отчёт и Git не включены. Идентификаторы подключения сохранены локально под Windows DPAPI. Схема БД не менялась.
