# 🔧 Исправление бага OAuth авторизации через Google

## **Проблема**
После входа через Google OAuth пользователя перекидывало на главную страницу, а при попытке перейти на другие страницы снова редиректило на страницу логина с ошибками.

## **Причина**
При OAuth авторизации сохранялся только токен `Authorization`, но **НЕ сохранялась** информация о пользователе (`Token` и `UserInfo`), которая необходима для полноценной работы приложения. Это приводило к тому, что при переходе между страницами система считала пользователя неавторизованным.

Сравнение:
- ✅ **Обычный логин**: Сохраняет `Authorization`, `Token`, `UserInfo`
- ❌ **OAuth логин (до исправления)**: Сохранял только `Authorization`
- ✅ **OAuth логин (после исправления)**: Сохраняет `Authorization`, `Token`, `UserInfo`

## **Решение**
Изменен файл `web/src/hooks/auth-hooks.ts`:

### Что было добавлено:
1. **Импорт необходимых модулей**:
   ```typescript
   import request from '@/utils/request';
   import api from '@/utils/api';
   ```

2. **Запрос информации о пользователе после получения токена**:
   ```typescript
   const { data: userInfoResponse } = await request.get(api.user_info);
   ```

3. **Сохранение полных данных пользователя** (как при обычном логине):
   ```typescript
   authorizationUtil.setItems({
     Authorization: token,
     userInfo: JSON.stringify(userInfo),
     Token: token,
   });
   ```

### Логика работы:
1. Пользователь авторизуется через Google
2. Backend возвращает auth токен через URL параметр `/?auth={token}`
3. **Frontend теперь**:
   - Сохраняет токен в localStorage
   - **Делает запрос к `/v1/user/info` для получения данных пользователя**
   - **Сохраняет все необходимые данные: Authorization, Token, UserInfo**
   - Редиректит на `/knowledge`
4. При переходе между страницами система находит все необходимые данные и не редиректит на логин

## **Как протестировать**
1. Перезапустить dev сервер (если запущен):
   ```bash
   cd web
   npm run dev
   ```

2. Открыть приложение и нажать "Sign in with Google"
3. Авторизоваться через Google
4. После редиректа попробовать перейти на другие страницы (/datasets, /next-chats и т.д.)
5. ✅ Пользователь должен оставаться авторизованным

## **Измененные файлы**
- `web/src/hooks/auth-hooks.ts` - основной файл с логикой OAuth callback

## **Дополнительные улучшения**
- Добавлена обработка ошибок при запросе user info
- Даже если запрос user info не удался, пользователь все равно останется авторизованным (есть токен)
- Добавлены console.log для отладки процесса

## **Состояние**
✅ **Баг исправлен**

Теперь OAuth авторизация работает так же, как и обычная авторизация - все данные сохраняются корректно, и пользователь может свободно перемещаться между страницами без редиректов на логин.
