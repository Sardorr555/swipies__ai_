1. Choose your workspace

Existing customer: use the existing account API key through your client's secret settings (SWIPIES_API_KEY for the stdio client). This keeps your datasets, agents and subscription.

New workspace: the stdio client can create an isolated Free service account automatically. It saves a random identity locally and reconnects to the same account on later runs. No browser registration or copied API key is required for this flow.

A newly registered account cannot access your other accounts or inherit Pro. Keep the local identity file private and backed up. This flow has no email recovery or account claiming.

2. Connect an MCP-capable client

Requires Python 3.10+; no third-party Python packages. Download the client to your machine and inspect it using your host's normal policy.

Download swipies_agent_client.py — if your browser saves a .txt extension, rename the file to swipies_agent_client.py.

Use the equivalent of this configuration in a host with stdio MCP support. Replace the path with the real absolute local path; use python3 if needed. The host controls its configuration format and tool permissions.

{
  "mcpServers": {
    "swipies": {
      "command": "python",
      "args": [
        "/absolute/path/swipies_agent_client.py"
      ]
    }
  }
}

Codex CLI:

codex mcp add swipies -- python /absolute/path/swipies_agent_client.py

Optional client flags: --url https://api.swipies.app, --state-file /private/path/identity.credential, --name "My AI workspace". Give independent customers separate state files or user profiles. Windows credentials use DPAPI; POSIX credentials are stored owner-only.

Direct HTTP instead of stdio

With an existing key, point a host supporting bearer-authenticated Streamable HTTP MCP to https://api.swipies.app/api/v1/agent-access/mcp. Configure Authorization: Bearer <your API key> securely and send User-Agent: SwipiesAgent/1.0. The endpoint uses POST, advertises protocol 2025-03-26, and does not offer server-initiated SSE sessions. GET/DELETE return 405.

An assistant with HTTP tools can also use the documented bootstrap and REST catalog. Read the full instructions before creating an identity; persist the generated secret before the first request.

3. Give your assistant the task

For example: “Create a knowledge dataset from the documents I provide, build a support chatbot and verify its answers against the sources.”

  1. Discover with swipies_list_operations.
  2. Read the selected API docs with swipies_describe_operation.
  3. Execute using swipies_execute and the discovered operation ID.
  4. Wait for parsing, test the result and retain the created resource IDs.

Available operations come from your running server and account. Do not guess operation IDs or retry an uncertain write before checking its result.

What is available?

Agents and chatbotsCreate, read, update, run and delete resources; inspect sessions and replies.
Knowledge and RAGCreate datasets, upload authorized documents, track parsing and retrieve source-grounded answers.
ConfigurationUse available model, channel and connector operations with the required credentials and permissions.
Current exclusionsAdministration, payments, token management, human login, OAuth callbacks and Ads are not in the generic MCP catalog.

Plans and boundaries

Free outputs include Swipies attribution. Only active persisted Plus and Pro plans can omit it. Account authorization, quotas and host permissions always apply. Private databases, model providers and OAuth services require valid authorized access; reading a page cannot supply those credentials or install a connector in every AI product.

MCP limits: 24 MiB request, 16 MiB combined uploads (20 files), 8 MiB result, 90-second operation timeout. Use smaller pages or direct REST for larger files and long-lived streams. Parsing is asynchronous.
